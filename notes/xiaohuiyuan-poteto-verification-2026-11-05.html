读书笔记：让 Agent 值得信任，先把"验证"和"代码库"做好

原帖：@xiaohuiyuan 2026-11-04 15:13（台北）（你点赞的那条）｜它读的是：@poteto 视频《here's how i shipped 2,500 PRs last month》，2026-09-21 23:01（台北），约 38 分钟。
我做的事：读完晓辉的长帖，再把 poteto 原视频整段转成英文文字稿逐段读（机器转写，个别段落有缺字，下面引文是我按转写翻成中文的大意）。笔记整理于 2026-11-05。

一句话结论：想同时让很多 Agent 干活，卡点不是模型，是你"敢不敢信它交的活"。信任靠两样东西换来——让 Agent 能自己跑起来检查结果的"验证技能"，以及一个干净到让 Agent 照抄也不会出错的代码库；纠错时优先改代码库和 lint，别只靠写规则。

核心观点（逐条 + 原文依据）

1. 一切都是"信任"问题。你只能盯 1–5 个 Agent，是因为还不信它；不信任就硬开 100 个，只会收到一堆烂 PR 和回归 bug。
晓辉："要让更多Agent帮你干活，本质还是构建信任trust"
poteto [5:13–6:36]：卡在"一个个聊天盯着纠正"的阶段最难走出来，原因就是不信任 Agent 的产出。
2. 验证技能 = CLI + Feature Map（特征地图）。CLI 让 Agent 能可重复地把应用跑起来、采集性能轨迹等证据；Feature Map 像"网站地图"，写清产品每块怎么运作、用户怎么用，Agent 收到一张模糊截图也知道去哪找。Feature Map 放在 skill 目录里，还有自动化定期维护它。
poteto [9:12–11:37]：第一个技能是通过 Chrome DevTools 协议跑应用、抓 trace；后来发现用户在 Slack 贴一小块截图加三个问号，Agent 只能瞎猜，于是做了 Feature Map，"一种具体化的记忆"。
晓辉："一个跟产品特征有关，一个跟可复用的代码和能力有关"

关于晓辉说"CLI 本质还不清楚"：按视频的说法，CLI 就是一个封装好的命令行工具，Agent 每次用同一套命令启动应用、收证据，不用每次现写脚本——晓辉的理解基本对。

3. 验证解决"对不对"，还要另一类技能解决"好不好"。验证能证明结账按钮能结账，但看不出性能和代码质量；所以她把资深工程师的做法（调试、开发、原型等）写成一套技能包 pstack。
poteto [12:33–14:13]
4. 纠正 Agent 的五个层次，越靠前越管用：
层是什么强制力
① 代码库最好的记忆，Agent 爱照抄现有模式最强
② 静态检查lint / 编译器 / CI，让错误"根本不可能发生"强
③ 规则 / Bugbot / 技能指导，Agent 可能漏读，用户也可能无视中
④ 风格指南只能靠人 review，PR 一多就看不过来弱

注：晓辉帖里把 rules/bug bot 和 skill 拆成两层，共 5 层；视频里 [15:38] 说"五个点"，口述时把规则、Bugbot、技能放在同一层讲。两种数法意思一致。

poteto [15:45–18:41]、[36:09]："如果你只记住一张幻灯片，就是这张。"
5. 坏模式会像病毒一样传播，团队需要"园丁"。一个小 workaround 或解释它的注释，几天到几周就被 Agent 抄遍全库。她举的例子：Agent 拿代码注释当理由"贴创可贴"不去真修，所以 Dune 框架里干脆限制注释（转写这句有缺字，具体规则待核）。原则三条：删已有技术债；每件事只留一条"官方正路"；看到坏模式第一反应是写 lint 规则先止血。
poteto [20:43–26:38]
6. 代码库要对"没背景的人"也友好。以后进代码库提交功能的可能是设计师、产品经理、CEO，Agent 被这些很忙、背景少的人驾驶时也要默认做对。
poteto [20:01–20:29]
7. 外环 + 内环：个人版"米其林厨房"。她不喜欢"软件工厂"这个词，更喜欢米其林厨房：你不再亲手切菜，但对出品负责，要设计好厨房。Grok Bot 接上 Slack、告警等做"外环"，用 routine 订阅事件自动拉起云端 Agent，自动复现 bug、自动开 PR。
poteto [0:55–1:58]、[32:33–34:58]

你能怎么用

工作（大厂 AI 产品经理）
  1. 给你的 CRM 需求写一份 Feature Map。每个模块：干什么、入口在哪、典型用户怎么用、常见报错长什么样。以后丢给 Agent 一张截图它能定位，也是 PRD 的好副产品。
  2. 把"验收"写成 Agent 能跑的清单。评审 AI 需求时多问一句"Agent 怎么证明自己做对了"——要有可跑的命令和证据（截图、数据、日志），而不是"自测通过"。
  3. 复盘纠错时按五层归类。同一类错误出现第二次，就推动落到"代码/校验规则"层，而不是再加一条提示词。这个框架也适合拿去跟研发对齐 AI 编码规范。
小红书「AI具身牛马」选题
  1. 《一个人一个月合 2,500 个 PR，她靠的不是更强的模型》——讲信任 + 验证，配五层表格做图卡（收藏型）。
  2. 《我给自己的 AI 情报站写了"验收清单"》——用你自己 x-digest 的真实例子：Agent 发布前自己截图、自检溢出，接你的「我用AI给自己搭了个情报站」主线。
  3. 《产品经理也能写的 Feature Map 模板》——给一页可抄的模板，收藏向。
