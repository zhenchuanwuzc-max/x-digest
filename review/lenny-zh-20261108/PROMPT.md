任务：为小红书选题素材池写中文素材卡元数据。只读原文，只写一个输出文件。
输入：本目录 {BATCH} 每行一个 Lenny Newsletter 原文 markdown 路径（中英对照）。逐篇完整阅读原文（不要只看标题）。
输出：写到 shards/{OUT}.json，一个 JSON 数组，每篇一个对象，字段：
- file: 文件名（不含目录）
- title_zh: 中文标题（自然中文，≤24字；可参考文件里 H1 的中文部分但要通顺）
- audience: 面向用户，具体到一类人和处境（如“第一次带 3-5 人 PM 小组的组长”“做 PLG 的 B 端 PM”“准备 PM 面试的转行者”），≤30字，禁止“产品经理/所有人”这种泛称单独出现
- reason: 推荐理由，≤70字，说清这篇能提供什么具体材料或决策依据（例如给出哪几条判断标准、哪个公司的做法、哪组问题清单），必须是原文里真有的内容；禁止“很有价值/干货满满/值得一读”之类空话
- angle: 切入视角，≤50字，一篇中文小红书图文能讲的一件具体事（一个问题或一个动作），不得编造 Ocean 或任何人的亲身经历，不得编原文没有的数据
- followup: 仅当文件在“已用”名单时填写（名单见下），≤50字，写可复盘或可延伸的方向（例如换一个用户场景、补原文没展开的一步），不得暗示重复发布同一内容；不在名单则填 ""
- evidence: 数组，2-3 条，每条 {"quote": 从原文逐字复制的一段连续文字（中文或英文均可，12-60字符，必须能在文件中原样找到）, "section": 该段所在的小标题或位置描述}
已用名单：{USED}
要求：全部用中文（quote 除外）；不同文章的 reason/angle 不得套同一句式；原文缺内容就写少不要编；写完自查 JSON 合法、每条 quote 能 grep 到。不要修改任何其他文件。
