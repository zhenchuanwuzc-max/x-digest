轴一 · 拆透每档差在哪

每一档回答五件事：行为标志（你在干什么才算到了）、必备技能（拆任务 / 写上下文 / 验收 / 评测 / 权限 / 数据接入）、成本、卡点、怎么跨到下一档。三段：个人 · 企业通用办公 · 电商垂直。

L0 · 旁观 / 偶尔问一句

时间轴：随时可进 · 几乎零成本

个人听说过 ChatGPT / 豆包，偶发问天气、翻译一句；输出不进工作流，也不存对话。
企业办公公司开了 Copilot 席位但登录率低；IT 发过邮件，业务当「又一个工具」。
电商刷到「AI 写标题」短视频，没注册；或注册了没用过店铺后台 AI。
技能：几乎无。卡点：不知道「问什么值得问」。

成本：0–几分钟；钱 ≈ 免费额度。

卡点：恐惧 / 没空 / 「跟我没关系」。

  1. 选一个每天都写的短文本（邮件/客服话术），连续 7 天用 AI 起草再改。
  2. 记下「哪次省了时间、哪次更糟」——这就是进 L1 的原料。

L1 · 会聊：单轮问答进日常

时间轴：约 1–2 周

个人写摘要、润色、解释概念成习惯；仍是「一问一答」，很少贴长文档。
企业办公用 ChatGPT/Copilot 写邮件、会议纪要；OpenAI 称典型企业仍偏「问答深度」，前沿企业人均智力用量约 3.5× 典型企业（2026-05 B2B Signals）。
电商用免费工具改标题/详情；淘天白皮书里约 70% 商家已在用 AI 工具、约 60% 每天高频用，但「L1 浅层应用」仍占 20.67%（淘天×《天下网商》白皮书，846 份问卷，见来源）。
技能：会写清楚问题；还不会系统贴上下文。缺：验收标准、评测。

成本：每天 15–40 分钟；订阅 0–20 美元/月。

卡点：幻觉没被抓住 → 不敢用在客户/老板面前；或「AI 写的一眼假」。

  1. 固定一个「可贴上下文」模板：目标 + 读者 + 约束 + 坏例子。
  2. 同一任务做 A/B：有上下文 vs 无上下文，比一次交付质量。
  3. 电商：把 10 条爆款标题结构拆出来再让 AI 仿写，人工筛。

L2 · 会喂：长上下文 + 多轮改稿

时间轴：约 1–2 月

个人上传 PDF/代码/表格；多轮「按这版改第三节」；开始有自己的 prompt 库。
企业办公知识库/定制 GPT 小范围试点；Microsoft WTI 类研究强调「使用深度」而非席位渗透（见来源）。
电商上传店铺数据截图/CSV 问「哪款该加投」；Shopify Sidekick Q1'26 周活店铺同比约 4×，近半 Flow 由 Sidekick 生成（财报）。
技能：写上下文、拆子任务。缺：可重复验收、权限与数据治理。

成本：搭模板 数小时–数天；企业还要合规评审。

卡点：上下文太散、模型「装懂」；企业侧数据进不了模型（权限墙）。

  1. 建「项目 README」：目标、术语表、禁止事项、成功样例。
  2. 每次交付附 3 条自检（事实 / 语气 / 格式）。
  3. 电商：把「类目词 + 卖点 + 禁词」固化成可复用块。

L3 · 会验：标准、评测、人机分工

时间轴：约 3–6 月

个人对代码跑测试、对文案对照清单；Mollick/BCG：前沿内任务质量↑、前沿外正确率↓19%——你会主动判断任务是否在 frontier 内。
企业办公有黄金集/抽检；区分 Centaur（切任务）与 Cyborg（融合工作流）。
电商上线前后比 CTR/转化；淘天白皮书口径「L3 深度应用」占 24.77%（淘天×《天下网商》白皮书，846 份问卷，见来源）。
技能：验收、评测、任务切分（在/出 frontier）。缺：系统权限编排、多 Agent。

成本：建评测集 数天–数周；组织要改 OKR/质检岗。

卡点：没有「错了谁负责」；METR 显示资深开发者早期-2025 用 AI 完成真实 issue 反而慢 19%，且自我感觉还快了 20%——验收不准会自我欺骗。

  1. 写清「AI 可自动合并」vs「必须人审」边界。
  2. 每周抽 10 条产出打分，盯错误类型分布。
  3. 电商：同一批素材用/不用 AI 做对照投放（小预算）。

L4 · 会编：Agent / IDE / 工具链进生产

时间轴：约 6–12 月

个人Cursor/Claude Code/Codex 日常改仓库；Andrew Ng：GPT-3.5 + agentic workflow 可超过 GPT-4 zero-shot（HumanEval 案例，约 48%→超 67% 量级，见字幕）。
企业办公前沿企业 Codex 消息量可达典型企业约 16×（OpenAI B2B Signals）；Cisco 称 Codex 助每月省 1500+ 工程小时、缺陷处理吞吐升 10–15×（同报告引用）。
电商Sidekick 代建页/自动化；Pulse 主动建议并执行；代运营用 Agent 批量出图+上架但仍人审价格库存。
技能：权限、工具调用、仓库/后台接入、失败重试。缺：多 Agent 编排与成本账。

成本：订阅+API 数十–数百美元/月；企业要改 CI、密钥、审计。

卡点：工具脆、权限窄、改完无人回归；组织激励仍奖「人肉加班」。

  1. 选一条端到端路径（issue→PR / 工单→回复）跑通自动化。
  2. 日志：每次 Agent 步数、失败原因、人工接管点。
  3. 电商：库存/价格写操作默认只读，写操作要二次确认。

L5 · 流水线：多 Agent + 数据闭环

时间轴：约一年以上 · 极少数人/团队

个人多 Agent 分工（规划/编码/评审）+ 夜间批任务；归藏观察：Personal Agent vs 专家可插拔 Agent 正在分化。
企业办公从聊天助手迁到「委托工作」；Travelers AI Claim Assistant 预计首年处理约 10 万次出险报案（OpenAI 案例）。
电商选品→素材→投放→客服→复盘闭环；淘天白皮书口径「L4 融合应用」仅 9.84%；海外卖家用 Catalog/AI 搜索流量（Shopify：AI 相关订单同比约 3×）。
技能：编排、评测门禁、成本/延迟账本、组织流程再设计。六项技能齐。

成本：工程周–月级；组织变革是主成本。

卡点：MIT NANDA「GenAI Divide」：任务型企业工具约 60% 评估→20% 试点→5% 成功落地；媒体常简化成「95% 试点失败」——见反证节精确表述。

  1. 先做一条窄流水线（一个 SKU 类目 / 一个代码子系统），设自动停机条件。
  2. 度量：人时、错误率、毛利，不单看「用了多少 token」。
  3. 把成功路径写成可复制 playbook，再扩面。

自测诊断表（约 2 分钟）

每题选最像你的一档；多数落在哪档，你大概就在哪。跨档看上一节 checklist。

题偏 L0–L1偏 L2–L3偏 L4–L5
Q1 上下文只打字提问常贴文档/数据，多轮改系统自动注入仓库/店铺/CRM
Q2 验收感觉还行就用有清单或测试门禁自动化 + 抽检仪表盘
Q3 工具网页聊天框定制 GPT / 知识库Agent + IDE/后台 API

Q5 组织个人偷偷用小团队规范流程与激励已按 AI 改过

L2–L3 故事

个人/知识工作 · BCG × Mollick 等

锯齿前沿上的顾问实验

试了：758 名 BCG 顾问，GPT-4，18 个前沿内真实咨询任务 + 1 个刻意选在前沿外的复杂任务。

前沿内：完成任务数 +12.2%，速度 +25.1%，质量显著更高；前沿外：正确解概率约 −19%。

奏效：Centaur（切任务给人/给 AI）与 Cyborg（深度融合）两种用法；失败：把前沿外任务也丢给模型还照单全收。

个人开发 · Andrew Ng agentic workflow

同一模型，换工作流就换档

试了：代码任务上对比 zero-shot vs agentic（计划–执行–反思–再改）。

反证 3 · 锯齿前沿本身就是反证

同一批顾问、看起来差不多难的任务，AI 可让你又快又好，也可让你更可能答错。深度 ≠ 处处加 AI，而是知道边界。

轴三 · 洞察做深

1. 为什么上手容易、用深难（机制）

  1. 验证成本：生成便宜、确认贵。METR 里人感觉快了 20%、实际慢 19%——没有外部计时/测试，主观会骗你。
  2. 隐性知识：好买家、好代码审、好客服话术里大量「说不清的规矩」；模型缺这些就会流畅地错。
  3. 上下文与数据墙：个人聊得欢；企业真数据、真权限、真审计一接上就停在 L2。
  4. 组织激励：KPI 仍奖人肉产出/工时；试点成功无人拥有规模化。NANDA：外部伙伴落地成功率约 2× 内部自建（报告口径）。
  5. 锯齿前沿（jagged frontier）：能力边界不平滑；任务看起来同级，一边加速一边害你。
  6. 能力悬垂（capability overhang）：模型已能做更深的事，多数人/组织仍停在问答；OpenAI：深度差距里消息量只解释约 36%，其余是更复杂委托。

2. 水位线怎么在挪

  • L1→L2 悬崖变矮：长上下文、截图、店铺内 Sidekick，使「喂材料」不再是极客技能。
  • L3 验收仍陡：评测集、对错标准、谁负责——组织债，模型帮不上太多。
  • L4 工具链在降坡：Cursor/Codex/Claude Code、Shopify Flow+Sidekick、连接器（如 1Password Agent 连接器，归藏 2026-10 观察）降低「接到生产」摩擦。
  • L5 编排仍贵：多 Agent + 闭环指标 + 停机条件，是产品与组织设计，不是再买一个聊天框。
  • 时间对照：Ng 2024 讲 agentic 时强调「要学会等迭代」；2026 企业信号已把 Codex/Agent 用量当前沿标志——悬崖位置下移，但验收与编排悬崖还在。

3. 每道悬崖上的钱与玩家

L0→L1 教育/习惯课程、模板、社群；玩家：各家官方学院、中文科普（宝玉等）、平台商家课堂。
L1→L2 模板与知识库提示词包、垂直知识库 SaaS、电商「标题/详情」工具。
L2→L3 评测与质检红队/评测公司、内容质检、人机抽检代运营；咨询把「试点变流程」。
L3→L4 接入与 Agent 工具IDE Agent、RPA+LLM、Shopify Sidekick/Amazon 卖家 AI、连接器；企业 IT 集成。
L4→L5 代运营 / 流水线产品托管式 AI 代运营、品类流水线、Agent 编排平台；吃的是组织不愿养团队的差价。
反模式只卖「席位」不卖深度 → 停在 NANDA 所说「有工具无回报」一侧。

4. 对 Ocean 的具体含义

  • iOS / 本地 Codex：你已偏 L4 工具链；下一悬崖是 L3 验收自动化（测试门禁、截图回归）和 L5 窄流水线（例如「一条功能：issue→云代理→PR→你只审」），而不是再多开聊天窗口。
  • Digest 情报站：本质是 L2→L3 产品——把信息差做成可验收的「今日可用动作」；加深页本身就是在补「验证成本」。
  • CRM / Accio 电商：卖家多数卡在 L1–L2；可卖的是 L2 模板（类目上下文包）+ L3 对照投放评测 + L4 只读连接后台；写操作默认人审，对齐 Shopify「代执行但可撤销」路径。
  • 别被 overhang 骗：模型与 Agent 能力涨得快，客户组织债涨得慢——报价按「帮对方跨一档」而不是按 token。
  • 反证自用：自己写代码时用 METR 提醒——感觉快 ≠ 真快；用锯齿前沿提醒——前端文案任务和库存决策任务不要同一套自动化。
