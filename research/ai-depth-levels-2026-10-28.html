AI 使用深度水位：上手容易、用深难

2026-10-30 · L0–L5 · 个人 / 企业办公 / 电商 · 数字附出处 · 未核实标「待核」

多数人能打开聊天框，少数人能把 AI 接到验收、工具链和业务闭环。下面按 L0–L5 拆清行为、技能、成本与卡点，并给出可核验的组织例与反证。

L0 · 旁观 / 偶尔问一句

时间轴：随时可进 · 几乎零成本

个人听说过 ChatGPT / 豆包，偶发问天气、翻译一句；输出不进工作流，也不存对话。
企业办公公司开了 Copilot / ChatGPT Enterprise 席位但登录率低；IT 发过邮件，业务当「又一个工具」。
电商刷到「AI 写标题」短视频，没注册；或注册了没用过店铺后台 AI。
代表（调查队列，非报告作者）：MIT NANDA《GenAI Divide》样本里，ChatGPT/Copilot 类工具探索或试点可超约 80%、部署近 40%，但多数价值停在个人效率、未必进 P&L：大量受访组织的席位持有者实质停在 L0–L1 之间（NANDA 是报告方，不是这一档的操作代表）。〔源〕 淘天白皮书「L0 尚未应用」约 6.18% 的商家队列（样本偏老板/决策层）。〔源〕
技能：几乎无。卡点：不知道「问什么值得问」。

成本：0–几分钟；钱 ≈ 免费额度。

卡点：恐惧 / 没空 / 「跟我没关系」。

  1. 选一个每天都写的短文本（邮件/客服话术），连续 7 天用 AI 起草再改。
  2. 记下「哪次省了时间、哪次更糟」：这就是进 L1 的原料。

L1 · 会聊：单轮问答进日常

时间轴：约 1–2 周

个人写摘要、润色、解释概念成习惯；仍是「一问一答」，很少贴长文档。
企业办公用 ChatGPT/Copilot 写邮件、会议纪要；OpenAI：典型企业仍偏「问答深度」，前沿企业人均智力用量约 3.5× 典型企业。〔源〕
电商用免费工具改标题/详情；淘天白皮书：约 70% 商家在用 AI、约 60% 每天高频，但「L1 浅层应用」仍占 20.67%。〔源〕
代表（调查队列 / 普及期行为，非报告作者）：OpenAI B2B Signals 所称「典型企业」中位用量用户队列：主要用来回答问题，而不是委托复杂执行（OpenAI 是报告方与模型提供方，不是这一档的操作代表）。〔源〕 Klarna 全员开通 ChatGPT Enterprise 初期、宣称约 90% 员工日活：这是席位普及队列（偏 L1–L2），不等于其后来的客服流水线（见 L5）。〔源〕
技能：会写清楚问题；还不会系统贴上下文。缺：验收标准、评测。

成本：每天 15–40 分钟；订阅 0–20 美元/月。

卡点：幻觉没被抓住 → 不敢用在客户/老板面前；或「AI 写的一眼假」。

  1. 固定一个「可贴上下文」模板：目标 + 读者 + 约束 + 坏例子。
  2. 同一任务做 A/B：有上下文 vs 无上下文，比一次交付质量。
  3. 电商：把 10 条爆款标题结构拆出来再让 AI 仿写，人工筛。

L2 · 会喂：长上下文 + 多轮改稿

时间轴：约 1–2 月

个人上传 PDF/代码/表格；多轮「按这版改第三节」；开始有自己的 prompt 库。
企业办公知识库/定制 GPT 小范围试点；OpenAI：开通权限已不再是差异点，重点转向使用深度。〔源〕
电商上传店铺数据截图/CSV 问「哪款该加投」；Shopify Sidekick Q1'26 周活店铺同比约 4×，近半 Flow 由 Sidekick 生成。〔源〕
代表（本档操作者）：Shopify（Sidekick：新商户前 30 天约一半对话在装修：典型「喂上下文」深度）〔源〕；Duolingo（GPT-4 生成练习/课程素材，学习设计师填 prompt 约束后人工审改：产品内容侧的 L2→L3 过渡）〔源〕；淘天白皮书「L2 常规应用」约 38.54%。〔源〕
技能：写上下文、拆子任务。缺：可重复验收、权限与数据治理。

成本：搭模板 数小时–数天；企业还要合规评审。

卡点：上下文太散、模型「装懂」；企业侧数据进不了模型（权限墙）。

  1. 建「项目 README」：目标、术语表、禁止事项、成功样例。
  2. 每次交付附 3 条自检（事实 / 语气 / 格式）。
  3. 电商：把「类目词 + 卖点 + 禁词」固化成可复用块。

L3 · 会验：标准、评测、人机分工

时间轴：约 3–6 月

个人对代码跑测试、对文案对照清单；Mollick/BCG：前沿内任务质量↑、前沿外正确率低约 19 个百分点〔源〕：你会主动判断任务是否在 frontier 内。
企业办公有黄金集/抽检；区分 Centaur（切任务）与 Cyborg（融合工作流）。
电商上线前后比 CTR/转化；淘天白皮书口径「L3 深度应用」占 24.77%。〔源〕
代表（本档操作者）：BCG（758 顾问实验，前沿外任务正确率掉约 19pp：验收/切任务本身就是能力）〔源〕；Ethan Mollick 总结的 Centaur / Cyborg 用法〔源〕；Duolingo Max（Roleplay / Explain My Answer：场景与初始句由人写，AI 回复持续抽检）〔源〕。反面教材：METR 早期-2025 RCT：资深开发者自我感觉快了 20%，实际慢 19%。〔源〕
技能：验收、评测、任务切分（在/出 frontier）。缺：系统权限编排、多 Agent。

成本：建评测集 数天–数周；组织要改 OKR/质检岗。

卡点：没有「错了谁负责」；验收不准会自我欺骗（见 METR）。

  1. 写清「AI 可自动合并」vs「必须人审」边界。
  2. 每周抽 10 条产出打分，盯错误类型分布。
  3. 电商：同一批素材用/不用 AI 做对照投放（小预算）。

L4 · 会编：Agent / IDE / 工具链进生产

时间轴：约 6–12 月

个人Cursor/Claude Code/Codex 日常改仓库；Andrew Ng：GPT-3.5 + agentic workflow 可超过 GPT-4 zero-shot（HumanEval：GPT-3.5 约 48%、GPT-4 约 67%）。〔源〕
企业办公前沿企业 Codex 消息量可达典型企业约 16×（OpenAI B2B Signals）；Cisco：构建时间约 −20%，每月省 1500+ 工程小时，缺陷吞吐 10–15×。〔源〕
电商Sidekick 代建页/自动化；Pulse 主动建议并执行；代运营用 Agent 批量出图+上架但仍人审价格库存。
代表（本档操作者）：
  • Cisco：Codex 进生产工程；AI Defense 新功能大量由 Codex 写；跨 15+ 仓优化构建；CodeWatch 缺陷修复吞吐 10–15×。〔源〕
  • Stripe：自研 Minions one-shot coding agents；官方称每周 1000+（后公开到 1300+）条无人写码、仅人审的合并 PR。〔源〕
  • Cognition（Devin）：对外销售的软件工程 Agent，自身以端到端仓库任务为产品形态：属 L4 代执行档的操作者，不是浅档报告作者。
  • Shopify：Sidekick 生成近半 Flow、自定义 App 与 Pulse「建议并执行」：电商侧的 L4 代执行。〔源〕
  • Box：组织级推广 Cursor 作核心 IDE/Agent（供应商案例口径，待交叉核）。〔源〕 待交叉核
技能：权限、工具调用、仓库/后台接入、失败重试。缺：多 Agent 编排与成本账。

成本：订阅+API 数十–数百美元/月；企业要改 CI、密钥、审计。

卡点：工具脆、权限窄、改完无人回归；组织激励仍奖「人肉加班」。

  1. 选一条端到端路径（issue→PR / 工单→回复）跑通自动化。
  2. 日志：每次 Agent 步数、失败原因、人工接管点。
  3. 电商：库存/价格写操作默认只读，写操作要二次确认。

L5 · 流水线：多 Agent + 数据闭环

时间轴：约一年以上 · 极少数人/团队

个人多 Agent 分工（规划/编码/评审）+ 夜间批任务；归藏观察：Personal Agent vs 专家可插拔 Agent 正在分化。
企业办公从聊天助手迁到「委托工作」并接进核心系统；度量人时/错误率/业务结果，而不只是 token。
电商选品→素材→投放→客服→复盘闭环；淘天白皮书「L4 融合应用」仅 9.84%〔源〕；Shopify：AI 搜索订单同比约 3×（流量侧闭环信号）。〔源〕
代表（本档操作者）：
  • Travelers：AI Claim Assistant 引导出险报案、答保单问题、在内部系统建案；预计首年约 10 万次 FNOL。〔源〕
  • Klarna：客服助手上线首月 230 万会话、约占客服聊天 2/3、约等于 700 名全职；解决时长从约 11 分钟降到不足 2 分钟；后续仍称约占 2/3 聊天并继续啃更复杂支持：这是 Klarna 自身跑在 L5 的流水线（模型供应商另计）。〔源〕 〔源〕
  • OpenAI / Anthropic 内部： frontier 实验室自身的多 Agent 研发、评测与部署流水线：作为本档操作者挂在 L5；勿与其报告里描述的「典型企业问答队列」混为一谈。
  • Salesforce Agentforce / ServiceNow AI Agents：厂商侧多 Agent 编排平台与客户部署叙事多，公开可独立审计的业务结果口径碎：作「平台能力」参考，不写成已验证的 L5 结果榜。待核
分布参照（非代表）：MIT NANDA 写任务型企业工具约 60% 评估→20% 试点→5% 称有持续生产力/P&L：真正站稳 L5 的组织极少。〔源〕
技能：编排、评测门禁、成本/延迟账本、组织流程再设计。六项技能齐。

成本：工程周–月级；组织变革是主成本。

卡点：编排、激励与停机条件；媒体常把 NANDA 简化成「95% 试点失败」：见反证节。

  1. 先做一条窄流水线（一个 SKU 类目 / 一个代码子系统），设自动停机条件。
  2. 度量：人时、错误率、毛利，不单看「用了多少 token」。
  3. 把成功路径写成可复制 playbook，再扩面。

自测诊断表（约 2 分钟）（带〔源〕的句子有出处，其余为归纳）

每题选最像你的一档；多数落在哪档，你大概就在哪。跨档看上一节 checklist。

题偏 L0–L1偏 L2–L3偏 L4–L5
Q1 上下文只打字提问常贴文档/数据，多轮改系统自动注入仓库/店铺/CRM
Q2 验收感觉还行就用有清单或测试门禁自动化 + 抽检仪表盘
Q3 工具网页聊天框定制 GPT / 知识库Agent + IDE/后台 API
Q4 失败时换个问法或放弃能说出错在哪类有重试/降级/人工接管剧本
Q5 组织个人偷偷用小团队规范流程与激励已按 AI 改过
Q6 数据不碰敏感数据脱敏后手工上传受控连接器 + 审计

粗判：≥4 题落左列 → 先攻 L2；中间居多 → 攻评测与权限进 L4；右列居多 → 盯成本和一条可复制流水线。

厚案例 + 反证

每档 2–3 个故事：试了什么 → 翻车 → 何物奏效 → 数字与出处。含个人 / 办公 / 电商（中国+海外）。

L0–L1 故事

企业办公 · 通用聊天工具普及

「席位开了，价值没进 P&L」

MIT NANDA《GenAI Divide》（2025）写：ChatGPT/Copilot 类工具探索或试点超过约 80%，部署近 40%，但主要抬个人效率，未必进损益表；任务型企业方案 60% 评估、20% 试点、5% 称有持续生产力或 P&L 影响。

漏斗：60% → 20% → 5%（任务型工具）

失败形态：当成「再发一个账号」，无验收、无工作流改写。

来源：MIT NANDA 报告 PDF / Fortune 访谈 Challapally（2025-08-18）

电商 · 中国平台分层

淘天商家 AI 融合指数层级（官方白皮书）

淘天集团 ×《天下网商》《AI重塑经营：2026中国电商AI应用白皮书》（2026-06 发布，06-10 对外公布）：调研 900 多位商家、有效问卷 846 份，按使用频率、业务覆盖率、工具数、人才储备、价值实现五维打分（满分 100）。L0 尚未应用 6.18%，L1 浅层应用 20.67%，L2 常规应用 38.54%，L3 深度应用 24.77%，L4 融合应用 9.84%；70% 商家在用 AI 工具，约 60% 每天高频使用。口径：受访者 85% 为老板/决策层，样本偏积极

注：淘天的 L0–L4 是他们自己的五档评分，和这里的 L0–L5 不一一对应，只能参照看。

来源：白皮书 PDF 原文 · 腾讯新闻报道 2026-06-10

L2–L3 故事

个人/知识工作 · BCG × Mollick 等

锯齿前沿上的顾问实验

试了：758 名 BCG 顾问，GPT-4，18 个前沿内真实咨询任务 + 1 个刻意选在前沿外的复杂任务。

前沿内：完成任务数 +12.2%，速度 +25.1%，质量显著更高；前沿外：正确解概率低约 19 个百分点〔源〕。

奏效：Centaur（切任务给人/给 AI）与 Cyborg（深度融合）两种用法；失败：把前沿外任务也丢给模型还照单全收。

来源：Dell'Acqua et al., SSRN 4573321；Mollick《Centaurs and Cyborgs on the Jagged Frontier》(2023-09-16)

个人开发 · Andrew Ng agentic workflow

同一模型，换工作流就换档

试了：代码任务上对比 zero-shot vs agentic（计划–执行–反思–再改）。

字幕口述：GPT-3.5 zero-shot 约 48% 正确；GPT-4 约 67%；给 GPT-3.5 套 agentic workflow 可超过 GPT-4 zero-shot。

奏效：reflection、工具使用、planning、multi-agent 四类模式；Ng 强调人要习惯「委托后等迭代」，不要只追求秒回。

来源：YouTube sal78ACtGTc 字幕 ≈00:02:46–00:03:18、00:03:48 reflection、00:09:20 multi-agent（本机 yt-dlp 拉取）

产品内容 · Duolingo

人写约束，模型出量，专家守门

试了：用 LLM 按 CEFR/主题/语法/题型 prompt 批量生成练习；Max 订阅用 GPT-4 做 Roleplay / Explain My Answer。

奏效：学习设计师填「Mad Lib」式约束，模型一次出多题，专家审改；场景与初始句仍由人写。失败风险：把生成当终稿、不做抽检。

来源：Duolingo《How Duolingo Uses AI to Create Lessons Faster》；Introducing Duolingo Max

电商海外 · Shopify Sidekick

从「问一句」到「代执行」

试了：主题改写、Flow 自动化、自定义 App、Pulse 主动建议并建页。

Q1'26：Sidekick 周活店铺同比约 4×；当季约 1.2 万+ 自定义 App；近一半 Flow 由 Sidekick 生成〔源〕。Q2'26：约 3400 万次对话；日活商户同比约 3.6×；自定义 App 约 3.6 万；引导新商户 15 天内达 5 单的比例 +8%。

新商户前 30 天约一半对话在装修；经营 5 年的商户分析类对话可过 40%：同产品不同深度。

来源：Shopify Q2 2026 电话会实录 · Q2 2026 投资者 deck；Q1 数字见 Q1 2026 电话会实录

L4–L5 故事

企业工程 · Cisco × Codex

把 Agent 当队友，而不是补全插件

试了：跨 15+ 仓库读构建日志与依赖图；CodeWatch 用 Codex CLI 在大型 C/C++ 上迭代修缺陷；Splunk 团队用其做 React 18→19 批量迁移。

构建时间约 −20%；每月省 1500+ 工程小时；缺陷解决吞吐约 10–15×；新 AI 功能 95%+ 由 Codex 写出（OpenAI/Cisco 联合披露）。

奏效：接入真实多仓、合规与评审流程；把 Codex 当「团队成员」跟计划文档，而不是聊天补丁。

来源：OpenAI × Cisco 案例（2026-05-27）；亦见 B2B Signals 转述

企业工程 · Stripe Minions

One-shot：Slack 一句 → CI 过的 PR

试了：完全无人值守的 coding agents；任务从 Slack/工单进来，在隔离 devbox 跑完，开出符合模板、过 CI 的 PR，工程师只审。

Stripe 官方：每周超过一千条合并 PR 完全由 Minions 产出、无人写码（后人引述到约 1300+/周）。

奏效：隔离环境 + CI/静态分析门禁 + 人审；擅长配置、依赖升级、小重构等边界清楚的任务。

来源：Stripe.dev《Minions》

机制洞察 · 水位漂移 · 搞钱地图

为什么上手容易、用深难（机制）（带〔源〕的句子有出处，其余为归纳）

  1. 验证成本：生成便宜、确认贵。METR 里人感觉快了 20%、实际慢 19%：没有外部计时/测试，主观会骗你。Stripe/Cisco 能上 L4，关键之一是 CI/评审把门，把验证成本机构化。
  2. 隐性知识：好买家、好代码审、好客服话术里大量「说不清的规矩」；模型缺这些就会流畅地错。Klarna 后来补「有温度」人工，正是承认边界外的隐性知识。
  3. 上下文与数据墙：个人聊得欢；企业真数据、真权限、真审计一接上就停在 L2。Travelers 的价值不在聊天，而在「能在内部系统建案」。
  4. 组织激励：KPI 仍奖人肉产出/工时；试点成功无人拥有规模化。NANDA：外部伙伴落地成功率约 2× 内部自建（报告口径）〔源〕。
  5. 锯齿前沿（jagged frontier）：能力边界不平滑；任务看起来同级，一边加速一边害你。
  6. 能力悬垂（capability overhang）：模型已能做更深的事，多数人/组织仍停在问答；OpenAI：深度差距里消息量只解释约 36%，其余是更复杂委托〔源〕。2026-06 Enterprise Signals 更新进一步写：前沿相对典型的人均输出 token 差距扩到约 8.3×（口径从 95 分位改为每月 top 10%，不可与 3.5× 直接横比）。〔源〕

水位线怎么在挪（带〔源〕的句子有出处，其余为归纳）

  • L1→L2 悬崖变矮：长上下文、截图、店铺内 Sidekick，使「喂材料」不再是极客技能。
  • L3 验收仍陡：评测集、对错标准、谁负责：组织债，模型帮不上太多。
  • L4 工具链在降坡：Cursor/Codex/Claude Code、Shopify Flow+Sidekick、Stripe 式内部 Agent 平台降低「接到生产」摩擦；但密钥、审计、回归仍要人建。
  • L5 编排仍贵：多 Agent + 闭环指标 + 停机条件，是产品与组织设计，不是再买一个聊天框。
  • 时间对照：Ng 2024 讲 agentic 时强调「要学会等迭代」〔源〕；2026 企业信号已把 Codex/Agent 用量当前沿标志：悬崖位置下移，但验收与编排悬崖还在。

每道悬崖上的钱与玩家（带〔源〕的句子有出处，其余为归纳）

L0→L1 教育/习惯课程、模板、社群；玩家：各家官方学院、中文科普博主、平台商家课堂。
L1→L2 模板与知识库提示词包、垂直知识库 SaaS、电商「标题/详情」工具；Duolingo 式「约束模板 + 人工审」也可产品化。
L2→L3 评测与质检红队/评测公司、内容质检、人机抽检代运营；咨询把「试点变流程」。
L3→L4 接入与 Agent 工具IDE Agent（Cursor/Codex）、RPA+LLM、Shopify Sidekick/Amazon 卖家 AI、连接器；企业 IT 集成。
L4→L5 代运营 / 流水线产品托管式 AI 代运营、品类流水线、Agent 编排平台（Salesforce Agentforce / ServiceNow 等厂商叙事）；吃的是组织不愿养团队的差价。
反模式只卖「席位」不卖深度 → 停在 NANDA 所说「有工具无回报」一侧。

对 Ocean 的具体含义（带〔源〕的句子有出处，其余为归纳）

  • iOS / 本地 Codex：你已偏 L4 工具链；下一悬崖是 L3 验收自动化（测试门禁、截图回归）和 L5 窄流水线（例如「一条功能：issue→云代理→PR→你只审」：对齐 Stripe Minions 形态），而不是再多开聊天窗口。
  • Digest 情报站：本质是 L2→L3 产品：把信息差做成可验收的「今日可用动作」。
  • CRM / Accio 电商：卖家多数卡在 L1–L2（淘天浅层+常规合计仍大头）；可卖的是 L2 模板（类目上下文包）+ L3 对照投放评测 + L4 只读连接后台；写操作默认人审，对齐 Shopify「代执行但可撤销」与 Klarna「可转人工」路径。
  • 别被 overhang 骗：模型与 Agent 能力涨得快，客户组织债涨得慢：报价按「帮对方跨一档」而不是按 token。
  • 反证自用：自己写代码时用 METR 提醒：感觉快 ≠ 真快；用锯齿前沿提醒：前端文案任务和库存决策任务不要同一套自动化。
