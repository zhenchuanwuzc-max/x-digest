产品是什么

官方自述README 说它把 Agent 编排成分阶段审计。六个阶段是侦察、按覆盖率狩猎、候选人否证、结构化输出、独立复核记录、以及与目标无关的报告。

官方自述它是 Cloudflare 漏洞发现流程的单仓库起点。博文是 Build your own vulnerability harness。博文讲的是他们后来的集群系统，这个仓库是起点，不是那套集群本身。

给谁

官方自述给已经有代码库、并让编程 Agent 做审计的人。安装用 npx skills add。触发语包括安全审计和找漏洞。没有沙箱时，README 要求把需要执行目标代码的线索留在 needs_validation，而不是直接跑。

工作流程与场景

官方自述侦察写 architecture.md 和 coverage-ledger.json。狩猎按账本分配互不复用结论的猎人。每个候选人交给一个新的验证者去推翻。findings.json 里的三种结论用 report-schema.json 校验。发现者不能当自己发现的验证者。

官方自述confirmed 要有完整的源码追溯和有边界的观察结果。needs_validation 只有一个未解决事实，不写严重度。rejected 记录被推翻的候选人。多次跑是叠加，旧结论不能当成已经覆盖。

事实校验脚本是仓库里的零依赖 Node 脚本。我们没有执行它。

真实使用信号

官方自述README 写他们自己的测试里，单次运行大约找到多次运行合计漏洞的一半。这是作者对内部测试的说法，没有附公开漏洞清单，我们不当成基准。

事实没有可以引用的 CVE 计数。星和 fork 只说明仓库被关注。

国内替代

假设国内团队缺的通常不是另一份通用英文技能，而是本公司的鉴权、租户隔离和导出接口清单。这次没有打开某一家国内安全产品的价目，所以不点名比较报价。

建议若要对照，对照的是流程差别。这里有独立否证和三种结论。一份只给「高中低」而不写未决事实的清单，不是同一件东西。

可做的窄切口

建议把本公司 20 条必查项写成狩猎附加清单。输出沿用 confirmed、needs_validation、rejected，而不是新发明等级。

最小版与不做的范围

建议选一个自己的玩具仓库。只跑到写出 findings.json，并用仓库里的校验脚本看它是否合格。不对外发布找到的问题。

不做不把这份技能包装成可以绕过目标系统的工具。不在没有沙箱时执行不可信代码。不承诺发现率。

验证办法与建议的成功和停止条件

建议成功是校验脚本接受这份 findings.json，并且每个 needs_validation 都写了一个可以继续查的事实。

建议停止条件是结论无法被人复核，或一次就把利用步骤发到了公开频道。

流量和付费

事实仓库免费、MIT。

假设能收费的是带本公司规范的审计服务，不是再发一个星标仓库。销售周期是团队采购，不是短视频成交。

风险

风险误报会消耗工程时间。把可利用细节写进工单或公开报告有合规问题。没有沙箱就执行目标构建，README 自己把它视为不够格的确认。
